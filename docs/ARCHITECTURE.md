# Architecture

## System Overview

Mo Headlines uses a **workflow-based architecture** separating content creation from content review. The system processes articles from multiple sources (RSS, manual research, YouTube) through a unified pipeline ending in an editorial review process.

### Core Workflow
```
Create Sources → Unified Queue → AI Processing → Review → Publish
```

## Data Flow Architecture

### Create Workflow
```
Generate Articles Modal → RSS Articles → Create Queue ↘
Research Modal → Research Articles → Create Queue → AI Processing → Articles (status: pending)
YouTube Modal → YouTube Articles → Create Queue ↗
```

### Review Workflow
```
Articles (status: pending) → Review Interface → Admin Decision → Articles (status: approved/rejected/draft)
```

### Publishing Flow
```
Articles (status: approved) → Public Website
```

## Component Architecture

### Shared Services

#### 1. Queue Management Service
**Location**: `/components/admin/create/shared/queue/`
- **Purpose**: Manages create_queue operations across all source types
- **Components**: QueueCard, QueueStats, QueueProcessor
- **Used by**: RSS tab, Research tab, YouTube tab

#### 2. Create Tab System
**Location**: `/components/admin/create/shared/tabs/`
- **Purpose**: Tab navigation specifically for Create section
- **Components**: TabsBar, Tabs
- **Used by**: Create section (RSS/Research/YouTube/Queue tabs)

#### 3. Create Shared Utilities
**Location**: `/components/admin/create/shared/`
- **Purpose**: Common utilities shared across Create workflow
- **Components**: StatusIndicator, ActionDropdown, CreateModal patterns
- **Used by**: All Create source types (RSS, Research, YouTube)

#### 4. Admin Layout Components
**Location**: `/components/admin/shared/`
- **Purpose**: Components shared across all admin sections
- **Components**: AdminSidebar
- **Used by**: Both Create and Review workflows

### Source-Specific Components

#### RSS Components
- **RssArticleCard**: Displays individual RSS articles with category, title, URL, excerpt, feed URL
- **GenerateArticlesModal**: Category selection, saved feed dropdown, feed testing, article import
- **Unique Features**: Feed testing, manual article generation, saved feed integration

#### Research Components  
- **ResearchSourceCard**: Manual creation status, concept preview, queue readiness
- **CreateResearchModal**: Title, URL, research concept input
- **Unique Features**: Manual workflow, research context display

#### YouTube Components
- **YouTubeSourceCard**: Video metadata, timecode display, transcript status
- **CreateYouTubeModal**: Video URL, timecode inputs, category selection
- **Unique Features**: Video-specific metadata, transcript generation status

### Design Consistency Through Workflow-Specific Utilities
- **Create Shared**: Queue management, Create tab system, Create-specific utilities
- **Review Shared**: Review tab system, Review-specific utilities  
- **Admin Shared**: AdminSidebar used across all admin sections
- **Design Tokens**: Shared styling system across all components

## AI Processing Pipeline

### Queue Processing Strategy
- Individual Processing (Phase 1)
- Batch Processing (Phase 2)

### Prompt Engineering Strategy
- **Universal Prompt**: Single prompt handles all source types using normalized queue data
- **Context Fields**: Title, URL, concept, createSource provide comprehensive context
- **Flexible Input**: Not all fields required - Perplexity adapts to available information
- **Quality Markers**: Consistent output format and quality criteria across all sources

## Integration Points

### Create → Queue
- **All Sources**: Generate via modals, store in respective tables, review in source tabs
- **RSS Articles**: Generate from feeds, display in RSS tab, add to queue when selected
- **Research Articles**: Create manually, display in Research tab, add to queue when selected  
- **YouTube Articles**: Generate from videos, display in YouTube tab, add to queue when selected
- **Queue Normalization**: All sources provide title, URL, concept, createSource for universal processing
- **Lifecycle**: Source articles deleted after queue addition, queue items deleted after processing

### Queue → Processing
- Configurable: individual vs batch processing
- Error handling and retry logic
- Processing status tracking

### Processing → Review
- Articles created with `status: "pending"`
- Automatic population of Review/Pending section
- Metadata preserved for source traceability

### Review → Publish
- Status change from "pending" to "approved"
- Automatic appearance on public website
- SEO optimization and social sharing preparation

## Performance Considerations

### Database Optimization
- Indexes on `articles.status` for Review workflow queries
- Indexes on `create_queue.status` and `create_queue.sourceType`
- Indexes on `saved_feeds.isActive` for feed selection
- Efficient category keyword matching for RSS filtering

### Queue Processing
- Configurable batch sizes based on API limits
- Rate limiting compliance with Perplexity API
- Background processing with status updates

## Security Architecture

### Authentication
- Clerk integration for admin access
- Role-based permissions for Create vs Review workflows
- API key management for external services

### Data Validation
- Zod schemas for all form inputs
- URL validation for RSS and YouTube sources
- Content sanitization before storage

### API Security
- Rate limiting on admin endpoints
- Input validation and sanitization
- Secure handling of external API keys

## Scalability Considerations

### Future Source Types
- Plugin architecture for new create types (Twitter, Podcasts, Conferences)
- Standardized queue interface for any source type
- Extensible prompt system for new processing requirements

### Performance Scaling
- Queue processing can be moved to background workers
- Database sharding by category or time period
- CDN integration for published articles

### Monitoring & Analytics
- Queue processing metrics
- Article engagement tracking
- Source performance monitoring
